# pi-simple-team 2.0.0

Teams now start work when they are spawned, resumed, or expanded. Existing teammates can be selected by name or Pi session ID in the same field. Lifecycle results show the complete team and its current activity.

## Breaking changes

- Tool names changed: `teamsend` → `team_send_message`, `teammain` → `send_main_message`, `teamstatus` → `team_status`, `teamlog` → `team_log`, `report_context_window` → `get_context_window_usage`, and `team_add` → `team_add_teammates`. Old names are not aliases.
- Spawn uses `teamName`. Teammate definitions use `systemPrompt`, `inheritMainContext`, `canManageOwnTeams`, and `showOnHerdrPane`. Undeclared input fields are rejected.
- Spawn, resume, and add start work automatically. Set `startIdle: true` to leave affected teammates idle. Already-live teammates continue their work.
- Messages, logs, and context usage use `targets`, which accepts team or teammate names and IDs. This replaces message `team`/`to` and log `team`/`teammate` selection. Ambiguous names return IDs that can replace them directly.
- Message `interrupt` accepts a boolean or a list of names/IDs that selects a subset of the recipients.
- Resume uses `resumptionPrompt` for one-time conversation instructions. It does not change saved system prompts. With `startIdle: true`, those instructions remain in context for a later turn.
- Results consistently use `teamName`, `teamId`, teammate `name`, and `teammateId`. The teammate ID is the Pi session ID. Spawn, list, and resume return complete teammate records. Add returns a lightweight complete roster. Previous parallel identity arrays and maps are removed.
- `live` means a live runtime. `active` means running or queued work. Lifecycle `started` reflects the entire team's activity, including pre-existing work. Resume identifies already-active teammates explicitly.
- Message results acknowledge `published: true`, rather than completed delivery. `team_send_message` returns statuses grouped by selected team. Later delivery failures are pushed to the original sender.
- Log cursors are opaque and support pagination across teams. Old cursors cannot be reused.
- Version-2 manifests live under `~/.pi/agent/pi-simple-team/teams-v2/`. Old team manifests are not loaded or migrated. Pi session files remain intact. Recreate team attachments after upgrading, or open retained Pi sessions directly.

## Other changes

- Automatic kickoff waits until the affected teammates are ready and restates each teammate's assignment for inherited context.
- Herdr startup uses `pane split`, `pane rename`, and `pane run`. Teams can mix RPC and Herdr teammates.
- Explicit team-wide Herdr settings override individual teammate settings.
- Success results provide the instructions needed after the call. Tool descriptions focus on invocation.
- Release automation accepts explicit major and minor versions while retaining automatic patch releases.

## Validation

All 256 tests passed, including real Pi lifecycle tests and release-workflow tests. A Luna test verified two same-named teammates, selection by ID, context usage, log pagination, complete rosters, and cleanup. Release workflow tests cover major releases, automatic patches, and rejected downgrades.
